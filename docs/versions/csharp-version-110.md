## Features

### Raw string literals

> 未加工の文字リテラル

Raw string literals can represent arbitrary text, including whitespace, newlines,
embedded quotes, and special characters, without requiring escape sequences.
The newline after the opening quotes and before the closing quotes isn't included in the final content.
Whitespace to the left of the closing triple quotes is trimmed from the string literal.

```cs
string longMessage = """
    This is a long message.
    It has several lines.
        Some are indented
                more than others.
    Some should start at the first column.
    Some have "quoted text" in them.
    """;

var location = $$"""
   You are at {{{Longitude}}, {{Latitude}}}
   """;
```

### Generic attributes

> 汎用属性

You can declare generic classes whose base class is `System.Attribute`.
This makes attribute syntax cleaner in scenarios that used to require `System.Type` parameters.

### UTF-8 string literals

> UTF-8 の文字列リテラル

.NET strings are stored as UTF-16, while UTF-8 is the standard for web protocols and lots of core libraries.
From C# 11 onward, you can add the `u8` suffix to string literals to mark UTF-8 encoding.
UTF-8 literals are represented as `ReadOnlySpan<byte>`.

```cs
ReadOnlySpan<byte> AuthWithTrailingSpace = new byte[] { 0x41, 0x55, 0x54, 0x48, 0x20 };
ReadOnlySpan<byte> AuthStringLiteral = "AUTH "u8;
```

### Newlines in string interpolation expressions

> 文字列補間式の改行

Text inside `{` and `}` in string interpolation can now span multiple lines.

```cs
var a = 1;
var b = 2;
var newLineInterpolationsMessage = $"a: {
    a
    }, b: {b}";
```

### List patterns

> リスト パターン

This checks whether sequence elements match corresponding nested patterns.

```cs
    if (value is [ pattern (, pattern)* ])
    {
        // ...
    }
```

Because sequence elements are matched by *nested patterns* rather than only constants, you can do things like:

- Use discard patterns to evaluate any pattern.
- Capture variables with `var` patterns.
- Use logical patterns like `and` / `or` and relational patterns like `>` / `>=`.
- Use property patterns.

and more.

### File-local types

> ファイルローカル型

The `file` modifier limits a top-level type's scope and visibility to the file where it's declared.
It's commonly used for types generated by source generators.

```cs
file class HiddenWidget
{
    // implementation
}

```

### Required members

> 必須メンバー

The `required` modifier means the target field or property must be initialized via an object initializer.

- You can apply `required` to fields and properties declared in `struct` and `class` types
    (including `record` and `record struct`).
- You can't apply `required` to `interface` members.
- `required` members must be initialized, but nullable reference types can still be initialized to `null`.
- A `required` member's visibility must be at least as wide as the containing type.
- You can't hide a `required` member declared in a base class.
- If a type parameter has a `new()` constraint, types with any `required` members can't be used as type arguments.
- You can't use `required` on positional parameters in record declarations.

You can use `SetsRequiredMembersAttribute` to indicate that a constructor initializes
all members, but note that compiler `required` checks are then bypassed.

### Auto-default structs

> auto-default 構造体

Any fields or auto-properties not initialized in a constructor are now automatically initialized by the compiler.

### Extended nameof scope

> 拡張 nameof スコープ

`nameof` expressions can now be used in parameter attributes for methods, local functions, and lambdas.

```cs
[ParameterString(nameof(msg))]
public static void Method(string msg)
{
    [ParameterString(nameof(T))]
    void LocalFunction<T>(T param) { }

    var lambdaExpression = ([ParameterString(nameof(aNumber))] int aNumber) => aNumber.ToString();
}
```
